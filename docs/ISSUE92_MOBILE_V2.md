# Issue #92 모바일 v2 구현 및 검증

## 구현 범위

- 하단 메뉴를 `프로젝트 / AI 팀 / PM 브리핑` 3개로 고정하고 `/`를 프로젝트 기본 화면으로 유지했다.
- 프로젝트 목록·필터·상세·4개 내부 메뉴·접이식 로드맵·업무 상태·결과·이력을 구현했다.
- 개발계에서는 프로젝트명, 목표, 설명, 선택 저장소, 단계 목표·완료 기준·담당 AI를 등록하고 단계 추가·삭제·순서 변경·수정할 수 있다.
- GPT(Codex)와 Claude 공유 사용량을 일별·주별 2열로 비교한다. 초기화 시각을 저장하고 남은 시간은 화면 시각 기준으로 계산한다.
- GPT, Codex, Claude Sonnet, Claude Opus의 수동 ON/OFF와 사용량 정책 제한을 별도로 관리한다. Claude 제한은 Sonnet과 Opus에 함께 적용되며 사용량 초기화가 수동 OFF를 변경하지 않는다.
- 업무 배정, 가상 실행, 검수 실패, 수정, 재검수, 완료, 실패, 사용자 승인·보류, AI 충돌, 사용량 제한·초기화를 브라우저 내 시뮬레이션으로 제공한다.
- 프로젝트·AI 팀·PM 브리핑은 하나의 상태를 사용하며 `localStorage`에 유지된다. 전체 새로고침에도 개발계 갱신 항목을 등록했다.
- 실제 GitHub, 운영 DB, Claude/Codex, 외부 콜백 및 배포 트리거를 호출하지 않는다. 기존 서버 DEMO_MODE 차단 정책은 변경하지 않았다.

## 개발계 데이터 경계

개발계 시뮬레이션은 `DEMO_MODE=1`이고 서버가 데모 활성 상태를 반환한 브라우저에서만 생성된다. 운영 또는 데모 비활성 상태에서는 조작 상태를 읽거나 만들지 않는다. 개발계 조작은 브라우저 저장소만 갱신하며 서버 mutation을 보내지 않는다. 실제 연동을 위한 사용량 필드에는 서비스, 기간, 사용률, 초기화 시각, 확인 시각, 출처를 분리했다.

## URL 호환

- `/` → 프로젝트 기본 화면
- `/activity` → `/briefing`
- `/tasks`, `/progress`, `/evidence` → `/projects`의 대응 상세 위치
- `/control` → `/agents#assignment-settings`

## 제한사항 및 후속 연동

- 시뮬레이션 상태는 개발계 브라우저별 저장소이므로 다른 기기나 브라우저와 공유되지 않는다.
- 실제 구독 사용량 공급자와 운영 프로젝트 저장소는 연결하지 않았다. 값이 없을 때 임의 수치를 만드는 대신 확인 불가로 표시하는 운영 경계를 유지한다.
- 실제 운영 DB 스키마나 마이그레이션을 변경하지 않았다.
- 개발계 배포 시 기존 안전 설정대로 `DEMO_MODE=1`, 비운영 `VERCEL_ENV`, 실제 자원 비밀 없음이 필요하다. 운영 환경에서는 DEMO_MODE가 fail-closed된다.
