## 결정한 것 (사용자)
- 작업 순서는 계획 → 감사 → 시작 → 구현·검수 → 반영이고, 시작·반영 조건은 모드별로 다르다. 자동 모드 꺼짐: 사용자가 `orch:go`로 시작하고, 위험한 최종 PR은 사용자가 Merge한다. 자동 모드(`ORCH_AUTO`) 켜짐: 감사 OK, 고칠 것 없음 판단, 마지막 라운드 때 자동 시작한다(마지막 라운드는 고친 계획이 유효하지 않아도 원래 계획으로 시작, 그 전 라운드에서 고친 계획이 유효하지 않으면 멈춤). 최종 PR은 위험과 상관없이 CI 통과 후 자동 반영한다. 화면이나 구조는 먼저 보여 주고 확인받은 뒤 작업한다.
- 사용자에게 무언가 해 달라고 요청할 때는 항상 링크를 같이 준다.
- 새 프로젝트는 `docs/NEW_PROJECT.md` 4단계를 따른다: 기본 환경 → 진행 단계 → 구조 확인 → 작업 시작.
- AI ON/OFF 스위치는 상황판 한 곳에서 모든 프로젝트에 적용한다.
- 검수는 Codex가 기본이고, Codex를 쓸 수 없으면 Opus가 대신한다. 구현은 Claude(Sonnet·Opus)가 한다 — 단, Claude 사용량 한도일 때 `ORCH_CODEX`·`ORCH_CODEX_DEV` 가 둘 다 켜져 있으면 Codex가 구현·수정을 대신한다. 그 스텝은 Claude를 쓸 수 있으면 Claude(Opus)가 독립 검수하고, Claude도 한도라 Codex가 검수해 임시 통과한 스텝만 최종 반영 전에 Claude가 다시 검수한다.
- 토큰 절약은 일단 PM 쪽 낭비를 줄이는 방식으로 한다(2026-11-24). 계획을 처음부터 꼼꼼히 써서 감사 라운드를 줄이고, 쉬운 스텝은 Sonnet으로 지정한다. Codex 구현 참여는 보류 — 단, Claude 한도 때만 Codex가 구현 대체(#329, `ORCH_CODEX_DEV`).
- 보호 경로(`.github/`, `scripts/orch/`) 변경은 PM이 브랜치 → PR로 올리고 사용자가 Merge한다(main 직접 push 금지, 2026-11-24).
- 운영 배포는 반영 10개마다 한다. 바로 보려면 deploy 워크플로를 수동으로 실행한다.

## 계획 작성 체크리스트 (감사 1라운드 통과 목표, 2026-11-24 결정)
계획 감사가 3라운드까지 가면 Claude 사용량이 많이 든다. 계획을 올리기 전에 PM이 아래를 직접 확인한다. 아래 항목은 오늘 감사에서 반복된 지적이다.
1. **실제 코드 확인**: 언급하는 파일·함수·줄 번호를 실제로 열어 보고 쓴다. 테스트 위치(`*.test.ts` 파일명), 기존 하네스(예: `github.test.ts`의 라우트 하네스), 화면 테스트 fixture 구조까지 확인한다.
2. **기존 테스트와 충돌**: 바뀌는 기대값을 `run.mjs`·fixture·forbid 문구에서 찾아서, '기존 검사는 위치만 옮기고 약화 금지, SUMMARY 기록'으로 미리 적는다.
3. **검증 가능한 완료 기준**: `done_when`은 기계로 확인 가능하게 쓴다. CI 잡 이름, 단언 내용, SQLSTATE, HTTP 코드, 호출 0회 같은 수준까지 적는다. 구현 환경에서 못 돌리는 것(psql 등)은 어느 CI 잡이 확인하는지 적는다.
4. **실패·경계 경우**: 부분 실패, 읽기 실패, 빈 입력, 토큰 없음, 재실행(멱등), 문자열 길이·좌표 상한을 미리 정한다.
5. **보호 경로와 선행 조건**: `.github/`·`scripts/orch/` 변경이 필요하면 PM이 먼저 PR로 반영하고, 계획에 '시작 조건: PR #N 반영(main SHA)'을 적는다.
6. **위험도**: DB·인증·워크플로·운영 설정을 건드리면 `auto_merge: false`로 한다(자동 모드 OFF일 때만 사람 머지를 강제하고, 자동 모드 ON이면 효과가 없다). 쉬운 스텝은 `"model": "claude-sonnet-…"` 대신 범위를 작게 나눠 Sonnet이 자동 선택되게 한다(위험 문구 남발 금지).
7. **보안·공개 저장소**: 로그·오류 메시지에 주소나 비밀값이 나오지 않게 하고, fixture·예시는 가짜 값만 쓴다.
8. 스텝 하나가 너무 크면(스키마+API+UI+문서) 나눈다. 데이터 계층과 화면은 분리한다.
