# 프로젝트 메타데이터: 실제 그룹핑 한계와 제안 (Issue #119, refs #116)

모바일 Projects 탭은 **GitHub Issue에 실제로 붙은 메타데이터만** 사용한다. 목표·프로젝트를 추정하거나 만들어 내지 않는다.

## 현재 규칙 (`src/lib/github/work-queue.ts`)

| 입력 | 결과 |
|---|---|
| `project:<이름>` 라벨이 **정확히 1개** | 프로젝트 `id = label:<이름>`, 이름 = `<이름>`, 목표 없음 |
| `project:` 라벨 0개 + 마일스톤 있음 | `id = milestone:<번호>`, 이름·목표 = 마일스톤 제목·설명 |
| `project:` 라벨 2개 이상 | **미분류** (모호하면 하나를 고르지 않는다) |
| 둘 다 없음 | **미분류** |

라우트 ID는 `label:<이름>` / `milestone:<n>`이며 콜론과 유니코드를 포함한다. 링크는 `encodeURIComponent`로 만들고,
화면은 경로 파라미터가 인코딩/디코딩 어느 형태로 와도 `src/lib/workspace/route.ts`의 `matchRouteId`로 안전하게(예외 없이) 일치시킨다.

## 실제 한계

1. **목표(goal)는 마일스톤 설명에서만** 나온다. 라벨 기반 프로젝트는 항상 "목표 미확인"이다.
2. 프로젝트 ID가 라벨 **이름**에서 파생되므로 라벨 이름을 바꾸면 이력이 다른 프로젝트로 갈라진다.
3. 라벨이 없는 기존(과거) 이슈, 예: 이 작업 큐의 다수 이슈는 전부 **미분류**로 모인다. 소급 변경하지 않았다.
4. `project:` 라벨이 2개 이상이면 미분류로 떨어진다(의도된 fail-closed).
5. 마일스톤과 라벨이 함께 있으면 라벨이 우선하고 마일스톤은 무시된다.
6. 단일 저장소(`jonghee1998/ai-orchestrator`)의 이슈만 그룹핑한다.

## 제안 (PM 소유 · 이 PR은 적용하지 않음)

- PM이 프로젝트마다 **명시적 `project:<slug>` 라벨 1개**(slug는 불변 영문 ID)를 소유하고, 새 이슈에만 적용한다.
- 목표가 필요한 프로젝트는 PM이 **마일스톤을 만들고 설명에 실제 목표를 적는다**(라벨과 마일스톤을 같이 쓰려면 규칙 5의 우선순위 변경이 필요하므로 별도 승인 필요).
- 과거 이슈의 라벨 소급 부여, 프로젝트 목표 문구 작성은 PM 결정 사항이며 이 변경에서 하지 않는다.
